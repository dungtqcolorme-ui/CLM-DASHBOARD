## 5. Campaign-First Workspace và collaboration

Campaign là root, không phải bốn tuyến bài. Có loại Seasonal (Chào Tân thường niên/Unitour) và Always-on (Sharing/Meme/InsideME). Optional sub-activities/event theo các điểm dừng; không coi AJC/HANU/BUV trong ví dụ là lịch 2027 đã xác minh.

Campaign lifecycle: `Draft -> Pending Activation -> Active -> Completed -> Archived`; có thêm `Paused` và `Emergency Hold` theo safety controller.
- Representative tạo Draft và chỉnh strategy, briefs, asset folders, assignments; Leader/Admin duyệt kích hoạt.
- Campaign Strategy Builder AI đề xuất objective, audience, message, Content Mix, KPI, phases, timeline, content pieces, workload và nguồn lực; dữ kiện thiếu ghi Chờ xác minh.
- KPI do AI gợi ý theo Organic baseline nếu đủ; Representative/Leader chỉnh KPI nháp, Leader/Admin xác nhận official KPI tại activation. Sửa KPI chính thức khi đang active phải có version mới, lý do, người xác nhận và giữ baseline cũ.

- Shared Plan với autosave, version history, conflict detection khi 2 người chỉnh cùng lúc; update không tự phá bài Approved/Scheduled.
- Content `production_status` và `publishing_status` là hai state machine khác nhau. Production: Not Started/Writing/Designing/Editing/Ready. Publishing: Draft/In Review/Changes Requested/Approved/Scheduled/Published/Failed/Cancelled.

## 8. Asset Library & Google Drive

Admin duy nhất quản lý Google Drive official connection/OAuth. Representative/Leader được chọn folder đã được cấp trong whitelist và gắn vào Campaign; folder ngoài danh sách cần review trước khi cho team dùng. Không scan toàn bộ Drive vô tội vạ. Kiểm tra scope hiện hành `drive.file` vs folder indexing; chọn least privilege hợp bài toán, tránh bypass bằng scraping.

Asset Library kết hợp Drive, Team Upload, Brand Assets. Per asset: source file ID/revision, provenance, event/campaign, author/uploader, rights/allowed uses/channels/expiration, dimensions/quality, tags, checksum, optional perceptual hash, original and derivative. Rights = Approved for Publishing / Needs Rights Review / Internal Only / Revoked. **Quyền đọc Drive KHÔNG đồng nghĩa được xuất bản.**

Image intelligence tìm theo semantics “ảnh sinh viên check-in tại booth”, nhưng không kết luận địa điểm/nhận diện cá nhân chỉ từ appearance. Event relevance and rights là điều kiện cứng. ## 10. Video & Motion Studio cơ bản — KHÔNG AI video / AI voice

Đường dẫn này không phải API token và **asset_id chưa chắc là Page ID**. Phải có màn hình onboarding Admin cho phép:

5. Hiển thị rõ mỗi capability: `Not Connected`, `Connected`, `Missing Scope`, `Needs App Review`, `Token Expired`, `Unsupported` và `Connection Error`, với lời giải thích/mục dẫn Admin. Không bao giờ hiển thị `Connected` nếu chưa xác minh.
6. Facebook Page Partnership là FIRST-CLASS TARGET; IG Professional và Threads là optional channels yêu cầu Admin xác minh từng identity/capability riêng. Không đồng nhất các endpoint hoặc định dạng.

**MCP Integration Policy**:
- Discovery tất cả MCP trong local Codex. Với `oliverames/meta-mcp-server`, lưu nhận xét archival/compatibility/version; kiểm tra code và scope thực tế. Không pin Graph API v21.0 theo README cũ nếu Meta đã thay đổi; đọc tài liệu hiện hành trước khi chọn bản API, pin version rõ ràng và test.
- Triển khai `MetaConnector` interface với typed operations: `verifyAccount`, `listAuthorizedAssets`, `readOwnedPosts`, `readPermittedComments`, `getSupportedOrganicMetrics`, `uploadMedia`, `scheduleApprovedPost`, `publishApprovedPost`, `cancelScheduledPost`, `getRemoteStatus`, `getCapabilities`. Implement mock and production adapters, structured errors, rate-limit and pagination.
- MCP trong **Codex developer environment** khác với quyền của **deployed Marketing Agent**. Deployed LLM chỉ được quyền đọc theo allowlist đã cấp; không thể trực tiếp gọi bất kỳ tools publish/delete/DM/comment/ads write. Publishing operations chỉ đi qua deterministic server-side Publishing Gateway với approved snapshot.
- Deny all by default đối với tool ngoài allowlist, đặc biệt create post/reels/media, cross-post, delete, reply comments, DM, ads campaign changes, account settings, purchases, external export. LLM không bao giờ quyết định bypass review hoặc gọi live write MCP trực tiếp.
- Nếu MCP repo đã archive, phụ thuộc lỗi hoặc quá rộng, cân nhắc tự viết typed Graph API adapter dùng các endpoints hiện hành; MCP chỉ phục vụ read-only (nếu an toàn). Không `npm install` ngẫu nhiên repo không được audit.
- Không tự test bằng cách đăng một bài thật hoặc gửi bình luận thật lên fanpage. Dùng mock fixtures, test Page chỉ khi Admin cấp rõ và tách khỏi production, và dry-run gateway trước.

**Publishing Gateway & state machine**:
- Content lifecycle: `Draft -> In Review -> Changes Requested -> In Review -> Approved -> Scheduled -> Published`. Trạng thái `Failed`, `Cancelled`, `Paused/Held` tách biệt khi cần. Publishing state khác Production state.
- Approval screen hiển thị chính xác: Creator, Assignee, reviewer, campaign/team, content version, text caption, tất cả media/design/video/thumbnail, source/rights, target Page/account, schedule date/time/zone, render hashes và previous revision diff.
- **Một hành động duy nhất `Duyệt & Lên lịch`** từ PR Leader/Admin hợp quyền, **khác Creator**. Server xác minh creator_id immutable, active roles, membership, campaign Active/no Hold, permitted media rights, verified Page, token/capability, latest content hash, scheduled time, proper account/channel and safe export. Cần transaction để tạo approval snapshot + durable publishing job.
- Freeze exact published payload hash. Nếu caption, image, video, account, time, target hoặc essential media metadata thay đổi sau Approved, create new revision and reapproval. Không để changed content tự thừa kế approval cũ.
- Scheduler: durable persisted job, unique idempotency key per approved snapshot + channel, transactional claim/locking, retry policy/backoff, reconciliation remote post IDs, dead letter, attempt audit. Không gửi hai lần do retry hoặc concurrent workers.
- Cần phân biệt scheduler nội bộ và lịch đã chuyển sang Meta. Chỉ thông báo "Đã hủy lịch" khi backend xác minh remote cancellation. Nếu Meta trả timeout, giữ `Cancellation Pending/Unknown` và alert.
- Post status receipt từ Meta phải verify; không tự suy ra `Published` từ HTTP request sent. Implement webhooks if permitted and signature-verifiable, else polling reconciliation compliant with API quota.
- `LIVE_META_PUBLISH_ENABLED` phải mặc định false ở dev/staging; production go-live là thao tác Admin/cấu hình có kiểm tra OAuth + quyền API + scheduler. **Ngay cả khi flag bật**, từng bài vẫn phải phê duyệt chéo.

## 12. Campaign Pause, Emergency Hold và an toàn race condition

- PR Representative có thể kích hoạt **Emergency Hold** ngay trong Campaign thuộc team, bắt buộc lý do; PR Leader/Admin có quyền xử lý và Resume. Leader/Admin có quyền Pause thông thường.
- Khi Hold, ghi immutable audit (actor, reason, timestamp, affected job IDs); atomically chặn job chưa thực hiện. Dispatcher đọc authoritative hold state ngay trước remote write; xử lý in-flight requests theo safety flow, kể cả request vừa bắt đầu.
- Đối với Meta-native scheduled posts: request cancellation qua adapter nếu supported, sau đó verify remote state và cập nhật từng bài là `Cancelled Verified` hoặc `Cancellation Pending/Unknown/Failed`. Nếu không supported: flag risk, người có quyền can thiệp thủ công theo hướng dẫn. Không báo giả "đã chặn tất cả".
- Bài đã Published không tự xóa. Resume không tự khôi phục lịch đã hủy hoặc tự đăng bù. Thay đổi schedule/caption/media cần approved snapshot hợp lệ mới; kể cả do Admin.
- Tạo concurrency tests: hold bấm cùng lúc dispatch, remote timeout/ambiguous response, cancel khi post vừa publish, revoked media giữa review và dispatch, resume rồi retry, duplicate cron, two approvers cùng action.
- Critical alerts tới assignee và Leader/Admin, có trạng thái acknowledged/resolved, không spam trùng; `read notification` khác `resolved incident`.

## 18. Test Matrix / Definition of Done

Tests bắt buộc:

**Auth/permissions**:
- Representative không activate Campaign; Viewer không write.
- Leader không approve bài chính họ tạo; Admin có nhiều roles vẫn không self-approve.
- Leader team A không duyệt team B; forged client role/header không có tác dụng; locked user bị chặn.
- Team membership revoked mid-session, cross-team RLS, secret table RLS.

**Campaign/workflow**:
- Draft -> Pending Activation -> Active; KPI freeze chính xác; v2 revision không làm mất v1.
- Shared Plan concurrent edits không mất dữ liệu; Content Mix 100% hợp lệ; approved scheduled posts không bị AI plan rewrite.
- Optional Task tạo/liên kết chỉ khi user action; không sửa legacy task ngoài đường API gốc.

**Research/privacy**:
- Internal Only không gọi external web; fake source không được chấp nhận; malicious instructions trong webpage/comment/Drive không kích hoạt tool ngoài quyền.
- Không tái sử dụng học bổng/khóa học/số liệu chiến dịch năm trước chưa xác minh.

**Asset/design**:
- Sai sự kiện/không rõ rights không eligible for publish. Revoked asset blocks scheduling; no automatic replace.
- Lock images/layout preserves selected layers; variants don't delete original. Logo aspect ratio constant, editable scene graph persists/reloads.
- KHÔNG có reachable image generation, video generation, AI voice or unrestricted MCP call path.

**Meta/safety**:
- Business Suite asset hint không bị dùng thẳng làm verified Page ID; wrong Page blocked.
- Missing permission/expired token -> disabled capability, never fake `Connected`.
- Approved snapshot must match publish payload; creator != approver enforced server/db.
- Concurrent publish retry -> only one remote post intent/receipt. Handle ambiguous timeout without false `Published`.
- Pause/Hold during dispatch, cancel remote failure, Resume without automatic republish, revoked rights after approval, expired token before schedule.
- No Ads mutations/comment reply/DM/live writes exposed to deployed AI.

**Intelligence**:
- Organic-only baseline, Paid/Unknown excluded, missing metric null not zero.
- Weekly/monthly report works with no data and says missing, external share requires separate human permission.

**Regression**:
- Login roles, original Dashboard, Task, Reports, Email/Calendar, Google auth, document catalog, Supabase operations remain working.

Run baseline and final checks `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm verify` where supported by actual package manager. Add targeted SQL/RLS integration tests, API tests, UI E2E smoke with mocks. Never test by public posting. Fix regressions caused by your changes; document pre-existing failures separately.
